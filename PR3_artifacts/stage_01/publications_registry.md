**Версия:** 1.1 (утверждена пользователем 14.11.2026; точечная фактологическая поправка к версии 1.0, состав A1–A7 не меняется).  
**Дата проверки:** 14.11.2026.  
**Тема:** «Сравнительный анализ моделей конкурентности для REST-сервиса: нативные Java-потоки, виртуальные Java-потоки, Kotlin coroutines, goroutines».  
**Основа:** требования ПР3 (шаг 1); библиографии НИР 1 и НИР 2; сверка по оригинальным страницам публикаций, текстам работ и научным каталогам.  
**Граница этапа:** подбор и проверка подходящих исследований. Заполнение всех 12 полей анализа экспериментальной методики и синтез — **этап 2**, в данном реестре они не подменяются пересказом.

## 2. Основная подборка — 7 статей

### [A1] Patryk Likuś, Filip Krużel (2025) — Java platform vs virtual threads в Spring

**Библиографическая ссылка:** Likuś, P., Krużel, F. *Analysis of Virtual Threads in Spring Applications*. In: Proceedings of the 39th ECMS International Conference on Modelling and Simulation, 2025, pp. 555–561. DOI: **10.7148/2025-0555**.

- DOI: https://doi.org/10.7148/2025-0555
- Полный текст (архив ECMS): https://www.scs-europe.net/dlib/2025/ecms2025acceptedpapers/0555_dis_ecms2025_0034.pdf
- Библиографическая проверка: https://researchr.org/publication/LikusK25
- **Эксперимент:** да. Авторы тестируют Spring REST API, сопоставляя платформенные и виртуальные потоки при разном соотношении вычислений и ожиданий, с контролируемым профилем HTTP-нагрузки.
- **Релевантность:** **очень высокая**. Прямой аналог JVM/Spring-части нашего исследования; важен также для логики выбора отдельных CPU-bound и I/O-bound сценариев.
- **Издание:** материалы конференции ECMS 2025.
- **Опубликованный артефакт:** при текущей проверке подтверждённой ссылки на воспроизводимый пакет не найдено. *Не означает, что артефакт точно отсутствует.*
- **Ограничение для дальнейшего анализа:** в статье используется симуляция ожидания внутри сервиса; наш согласованный I/O-сценарий использует **отдельный реальный HTTP-эмулятор**, поэтому перенос выводов требует оговорки. Доступ к PDF у некоторых серверов может быть ограничен (403), хотя индексируемый полный текст доступен через поиск.

### [A2] Michał Grabowiec, Sebastian Wiktor, Jakub Smołka (2024) — Kotlin coroutines vs потоки, включая virtual threads

**Библиографическая ссылка:** Grabowiec, M., Wiktor, S., Smołka, J. *Performance analysis of coroutines and other concurrency techniques in Kotlin language for I/O operations*. Journal of Computer Sciences Institute, 2024, vol. 33, pp. 306–312. DOI: **10.35784/jcsi.6353**.

- DOI: https://doi.org/10.35784/jcsi.6353
- Страница журнала: https://ph.pollub.pl/index.php/jcsi/article/view/6353
- Полный текст: https://yadda.icm.edu.pl/baztech/element/bwmeta1.element.baztech-ecaf73f2-fbd8-401c-9c45-b43420f001a6/c/jcsi33_2024_306-312.pdf
- **Эксперимент:** да. Реализованы сравнения корутин, обычных потоков, пулов и виртуальных потоков для операций с файлами и взаимодействия с тестовым REST API; используются тесты производительности и контроль ресурсов.
- **Релевантность:** **очень высокая**. Особенно полезна для проектирования `GET /io` с управляемым внешним HTTP API и для корректной интерпретации поведения Kotlin coroutines.
- **Издание:** научный журнал *Journal of Computer Sciences Institute*, представлен в DOAJ; рецензируемое издание.
- **Опубликованный артефакт:** ссылка на полный репозиторий или пакет данных при проверке не подтверждена.
- **Существенная оговорка:** авторы прямо указывают, что в одном из REST-тестов результат для виртуальных потоков не приводился из-за ограничений выбранного HTTP-клиента. **Нельзя выдавать статью за полностью симметричный REST-бенчмарк всех моделей.**

### [A3] Andrea Rosà, Matteo Basso, Leonardo Bohnhoff, Walter Binder (2023) — platform/virtual threads и поведение веб-сервера

**Библиографическая ссылка:** Rosà, A., Basso, M., Bohnhoff, L., Binder, W. *Automated Runtime Transition between Virtual and Platform Threads in the Java Virtual Machine*. Proceedings of the 30th Asia-Pacific Software Engineering Conference (APSEC), IEEE, 2023, pp. 607–611. DOI: **10.1109/APSEC60848.2023.00080**.

- DOI: https://doi.org/10.1109/APSEC60848.2023.00080
- Полный текст авторов: https://www.dag.inf.usi.ch/wp-content/uploads/APSEC23-CR.pdf
- Каталог DBLP: https://dblp.org/rec/conf/apsec/RosaBBB23
- **Эксперимент:** да, **предварительная оценка прототипа** на веб-сервере Eclipse Jetty, с переходом между типами потоков и сопоставлением пропускной способности в зависимости от нагрузки.
- **Релевантность:** **высокая**. Даёт основание рассматривать тип конкурентности как фактор с эффектом, зависящим от характера задачи, и обосновывать необходимость профилей нагрузки.
- **Издание:** конференция IEEE APSEC 2023.
- **Опубликованный артефакт:** полный текст доступен; отдельный открытый репозиторий/образ не подтверждён.
- **Ограничение:** работа прямо обозначена авторами как *work in progress*; использует экспериментальную модификацию JDK 20, а не стабильную конфигурацию современного Spring Boot. Это не эквивалент нашего будущего стенда.

### [A4] Mia Šimatović, Helena Markulin, Dora Beronić, Branko Mihaljević (2025) — виртуальные потоки, CPU/память/GC

**Библиографическая ссылка:** Šimatović, M., Markulin, H., Beronić, D., Mihaljević, B. *Evaluating Memory Management and Garbage Collection Algorithms with Virtual Threads in High-Concurrency Java Applications*. Proceedings of the 48th MIPRO ICT and Electronics Convention, 2025. DOI: **10.1109/MIPRO65660.2025.11131846**.

- DOI: https://doi.org/10.1109/MIPRO65660.2025.11131846
- Полный текст (университет авторов): https://www.rit.edu/croatia/sites/rit.edu.croatia/files/docs/Evaluating%20memory%20management%20and%20garbage%20collection%20algorithms...%2C%20Simatovic%20et%20al.%2C%202025.pdf
- **Эксперимент:** да. Сравнение обычных и виртуальных Java-потоков под несколькими алгоритмами GC на CPU-, memory- и I/O-нагрузках с измерением времени, CPU и heap.
- **Релевантность:** **высокая** по метрикам CPU, heap, GC и дизайну повторных запусков. Данные относятся к JVM, поэтому **не переносятся напрямую** на Go Runtime.
- **Издание:** конференция MIPRO 2025 / IEEE DOI.
- **Опубликованный артефакт:** отдельный репозиторий или открытый набор данных не подтверждён.
- **Ограничение:** не полноценный REST end-to-end бенчмарк, а набор прикладных сценариев и вычислительных тестов.

### [A5] Luiz Otávio Soares, Ricardo Terra (2024) — Go vs Java в REST/gRPC

**Библиографическая ссылка:** Soares, L. O., Terra, R. *Go x Java e gRPC x REST: Um estudo empírico* [«Go vs Java и gRPC vs REST: эмпирическое исследование»]. Proceedings of the Brazilian Symposium on Programming Languages (SBLP), 2024, pp. 62–70. DOI: **10.5753/SBLP.2024.3686**.

- DOI: https://doi.org/10.5753/SBLP.2024.3686
- Полный текст (университет авторов): https://professores.dcc.ufla.br/~terra/publications_files/2024_sblp.pdf
- Полный текст (издатель SBC): https://sol.sbc.org.br/index.php/sblp/article/download/30258/30065/
- DBLP: https://dblp.org/rec/conf/sblp/SoaresT24.html
- **Эксперимент:** да. Факторный эксперимент с четырьмя вариантами (Java/Go × REST/gRPC), различными размерами запросов и статистическими проверками.
- **Релевантность:** **очень высокая** для межплатформенной части темы; показывает, почему влияние языка/среды нельзя неявно приписывать исключительно модели конкурентности.
- **Издание:** сборник научной конференции SBLP 2024 (SBC, DOI и DBLP).
- **Опубликованный артефакт (уточнение этапа 2):** авторы в §3.9 статьи дают ссылку https://github.com/PqES/2024_sblp ; проверено наличие Go/Java реализаций HTTP/gRPC, клиента, тестовых данных и R-скриптов. Полностью зафиксированного контейнерного окружения не подтверждено.
- **Ограничение:** исследование не изолирует собственно goroutines от остальных различий Go/Java; выбранные там эффекты нельзя переносить на нашу H₁ напрямую.

### [A6] Sergio Di Meglio, Luigi Libero Lucio Starace (2024) — воспроизводимый benchmark REST-фреймворков

**Библиографическая ссылка:** Di Meglio, S., Starace, L. L. L. *Evaluating Performance and Resource Consumption of REST Frameworks and Execution Environments: Insights and Guidelines for Developers and Companies*. IEEE Access, 2024, vol. 12, pp. 161649–161669. DOI: **10.1109/ACCESS.2024.3489892**.

- DOI: https://doi.org/10.1109/ACCESS.2024.3489892
- Страница IEEE: https://ieeexplore.ieee.org/document/10741246/
- Запись в DOAJ: https://doaj.org/article/b8024eacd4c645c8a8150b04b3bfdc93
- **Открытый артефакт:** Zenodo **v2**, https://zenodo.org/records/13495203 ; DOI артефакта: **10.5281/zenodo.13495203** (предыдущая версия v1: 10.5281/zenodo.12722085).
- **Эксперимент:** да. Сравнение 12 конфигураций REST-приложений с автоматизированным исполнением тестов, анализом производительности и ресурсоёмкости.
- **Релевантность:** **очень высокая для научной воспроизводимости**. Пакет подтверждён: исходный код разных REST-приложений, Docker-окружения, скрипты JMeter, результаты повторений, скрипты запуска, статистический анализ на Python и R.
- **Издание:** рецензируемый журнал **IEEE Access**.
- **Важное ограничение:** не прямое сравнение четырёх заданных моделей конкурентности и **не исследование Go/goroutines**; используется как образец дизайна и воспроизводимого артефакта. Архив большой (~362 МБ), при проверке **не скачивался и не запускался**: подтверждён состав пакета по Zenodo, но не факт исполнимости в нашем окружении.

### [A7] Salsabila Yunita Sari, Felix David (2026) — модели конкурентности Go для I/O-bound обработки

**Библиографическая ссылка:** Sari, S. Y., David, F. *Performance and Stability Evaluation of Concurrency Models for I/O-Bound Services in Golang under High-Volume Transaction Load*. *International Journal Software Engineering and Computer Science (IJSECS)*, 2026, vol. 6, no. 2, pp. 615–626. DOI: **10.35870/ijsecs.v6i2.7490**.

- DOI: https://doi.org/10.35870/ijsecs.v6i2.7490
- Страница статьи и доступ к PDF: https://journal.lembagakita.com/ijsecs/article/view/7490
- Независимая библиографическая запись: https://garuda.kemdiktisaintek.go.id/documents/detail/6695648
- **Эксперимент:** да. Сравниваются последовательная обработка, неограниченное создание goroutines и worker pool с backpressure при обработке **11 миллионов записей** с использованием PostgreSQL. Рассматриваются производительность, устойчивость и последствия перегрузки (включая OOM).
- **Релевантность:** **высокая для I/O-bound сценария и ограничений конкурентности в Go**. Полезна для обоснования backpressure, контроля внешней зависимости и ресурсных ограничений; дополняет A5, уже содержащую сравнение Java и Go на уровне REST/gRPC.
- **Издание:** научный журнал IJSECS, выпуск от 01.08.2026. На сайте заявляется рецензирование, но **для обязательной квоты ≥2 рецензируемых публикаций на это подтверждение не полагаемся**.
- **Окружение, указанное в аннотации:** Docker-контейнеры на Colima VM; 4 CPU, 8 ГБ RAM, максимум 50 подключений к базе; предварительная калибровка размера пакета.
- **Опубликованный артефакт:** открытая страница статьи и PDF подтверждены; отдельный репозиторий с полным кодом, зафиксированным окружением и сырыми результатами **пока не подтверждён**.
- **Принципиальное ограничение:** это **не REST HTTP benchmark и не прямое сравнение с Java**. В нашем базовом I/O-сценарии используется отдельный HTTP-эмулятор, а не БД. Нельзя переносить цифры обработки PostgreSQL на RPS REST-сервиса. Точные сведения о повторениях, статистических тестах и возможности воспроизведения изучим на этапе 2.

**Решение о замене:** включена вместо Lozić, Bralić и Filipović (2025) по прямому согласованию пользователя от 14.11.2026. Предыдущая A7 перенесена в резерв как **R5**; отдельная проверка сохранена в [`A7_verification_and_alternatives.md`](./A7_verification_and_alternatives.md).

## 5. Что было уточнено по сравнению с предыдущими НИР

1. **Фактическая смена тематического охвата:** исходные НИР сосредоточены на JVM. В подборке две экспериментальные публикации по **Go**: A5 (межплатформенное REST/gRPC) и A7 (I/O-bound обработка на Go с PostgreSQL и backpressure). Прежняя статья A7 о goroutines vs Java threads находится в резерве как R5.
2. **Дополнена релевантная литература по корутинам:** A2 (2024) непосредственно сопоставляет coroutines с Java-потоками и тестирует обращение к внешнему REST API; этот источник полезнее для нашего I/O-сценария, чем общий обзор Kotlin.
3. **Скорректирован порядок авторов ECMS:** у статьи A1 — **Patryk Likuś, Filip Krużel**. В прежней НИР порядок был обратным; в новом реестре он сверен по титульной странице.
